# إعداد studio — ضغطة واحدة (v0.1.41)

مثبّت واحد بأمر واحد. بلا حسابات وبلا مفاتيح وبلا إنفاق،
ولا يلمس المنشورات المجدولة ولا الطابور ولا بيانات العملاء.

## البدء السريع

```bash
cd ~/workspace/studio
bash setup.sh            # كل شيء إلا الثقيلتين (كسولتان)
bash setup.sh --dry-run  # اعرض الخطوات فقط — بلا أي تنفيذ
bash setup.sh --check    # افحص الحالة فقط — بلا تثبيت
bash setup.sh --with whisper,moviepy   # وثبّتهما مقدمًا
bash setup.sh --full     # كل شيء بما فيه الثقيلتان
bash setup.sh --path-dry-run  # اعرض تغييرات PATH فقط — بلا كتابة
bash setup.sh --path-only     # طبّق كتلة PATH فقط + تحقق منها
bash setup.sh --remove-path   # احذف كتلة PATH (تراجع)
bash setup.sh --no-path       # تثبيت كامل بلا لمس ملفات بدء التشغيل
```

الخروج: `0` إن نجحت الفحوصات الأساسية، و`1` إن فشل أي منها.
إعادة التشغيل آمنة: لا يعيد ما اكتمل. `--dry-run` يخرج `0` دائمًا.

## التثبيت الكسول (lazy install)

`whisper` ‏(478M) و`moviepy` ‏(269M) لا تُثبَّتان مقدمًا.
تُثبَّتان بإحدى الطرق:

```bash
bash setup.sh --with whisper          # مقدمًا
bash setup.sh --with whisper,moviepy  # مقدمًا
python3 -m lib.ensure_env install whisper   # يدويًا عند الحاجة
python3 -m lib.ensure_env install --heavy   # كلتاهما
python3 -m lib.ensure_env install --shared  # الخفيفات فقط
python3 -m lib.ensure_env check [--json]    # الحالة فقط
python3 -m lib.ensure_env verify [--shared|--all|TOOL ...]  # تحقق SHA-256
```

وحدة `lib/ensure_env.py` هي السجل الوحيد للحقيقة (كل أداة ←
حزمها المثبّتة واختبار استيرادها وثقلها)، بلا أي أثر جانبي عند
الاستيراد وبلا شبكة إلا عند `install` صراحةً. دالة `ensure(name)`
تنشئ البيئة (ذريًا) وتثبّت حزمها (باحتياطي متدرج) وتتحقق من
الاستيراد وبيانات التثبيت، وتُرجع `(ok, message)`.

**الربط الكسول في مواضع الاستدعاء — مؤجل موثَّق:** لم تُربط
`ensure()` بعد داخل `lib/whisper_captions.py` و`lib/moviepy_fx.py`
و`lib/ref_analyzer.py` (تعديلها خارج ملكية هذه الحزمة). الربط
المقترح سطر واحد قبل استخدام مفسّر البيئة الثقيلة:

```python
from lib import ensure_env
ok, msg = ensure_env.ensure("whisper")
if not ok:
    raise WhisperError(msg)
```

حتى يُربط، رسائل الخطأ الحالية في تلك الملفات تشير إلى
`setup.sh` كما هي، والتثبيت اليدوي بالأمر أعلاه يعمل. ملاحظة:
`moviepy` ‏(269M) أغلبها حزمة ffmpeg مضمّنة ‏(165M) رغم وجود
ffmpeg في النظام — تقليلها يحتاج تغيير اعتماد moviepy نفسه
(خارج النطاق).

## التوافق مع الإصلاح الذاتي

لا شيء يتغير في آليات الإصلاح الذاتي الحالية، وثبت ذلك باختبار
(انظر «التحقق»):

- `setup-env.sh` v3 + `ensure-env.sh` + خطافا `~/.bashrc` و
  `~/.profile`: لا تمس البيئات الافتراضية أصلًا (تعيد أدوات
  النظام وملف الخدمة فقط) — فلا تتعارض مع الدمج ولا مع الكسل.
- بيئة قديمة حقيقية (`.venv-gtts` مثلًا) تُحترم كما هي ولا
  تُستبدل برابط رمزي؛ و`ensure_env.resolve_python()` يفضّلها.
- بيئة ثقيلة قديمة معطوبة لا تُحذف تلقائيًا — يُرجع `ensure()`
  الأمر اليدوي لحذفها (حذف بيانات المستخدم يحتاج قراره).
- `doctor` يفحص `.venv-youtube/bin/python` — يمر مباشرة لأن
  المشتركة تسكن هناك؛ والروابط الرمزية تمر أيضًا عبر
  `os.path.isfile`.
- المثبّت لا يعدّل `~/.local/bin` ولا أي بيئة حية؛ ويلمس
  `~/.bashrc` و`~/.profile` فقط لإضافة كتلة PATH المعلَّمة
  (قابلة للحذف بـ `--remove-path`)، ولا يمس أي سطر آخر فيهما.

## استكشاف الأخطاء

- `doctor` يفشل على **موديل صوت Piper** أو **headless-editor**:
  ملفان خارج المستودع (في `~/workspace/`) — نزّلهما/استنسخهما
  كما يقول سطر `[FAIL]`، أو شغّل سكربت استعادة البيئة. هذا
  سلوك قائم قبل هذه الحزمة وليس منها.
- `doctor` يفشل على **حماية المشروع (protect)** بعد تثبيت جديد:
  يجب ألا يحدث مع التسمية الحالية (المشتركة في `.venv-youtube`
  مستثناة). إن حدث، أبلغ المنسق — لا تحذف ملفات يدويًا.
- `verify` يفشل (مجموع لا يطابق / ملف مفقود): أعد التثبيت
  (`python3 -m lib.ensure_env install --shared` أو للأداة
  نفسها)؛ وإن تكرر، تحقق من مساحة القرص.
- مساحة قرص حرة غير كافية: `setup.sh` يوقف التثبيت قبل
  بدئه ويطبع المطلوب — حرّر مساحة ثم أعد التشغيل.
- `auto-editor` ينزّل ثنائيًا عند أول تشغيل: سلوك الأداة نفسها
  (ليس من المثبّت) — يحتاج شبكة مرة واحدة.
- حزم النظام لا تُثبَّت تلقائيًا بلا sudo بلا كلمة سر: نفّذ الأمر
  المطبوع يدويًا ثم أعد `bash setup.sh`.
- بيئة ثقيلة معطوبة: `ensure()` يطبع أمر الحذف وإعادة التثبيت
  اليدوي — نفّذه كما هو.
- كتلة PATH لا تظهر في shell جديدة: افتح shell جديدة تمامًا
  (الكتلة تُقرأ عند البدء لا في الجلسة الحالية)، أو شغّل
  `bash setup.sh --check` لرؤية حالة الكتلة والتحقق.
